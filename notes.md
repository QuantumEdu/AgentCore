# Notes

## Orden recomendado como flujo lógico

### 1. governance
Primero defines:
- reglas del juego
- gates
- read order
- cómo entra el usuario al sistema

### 2. quick-start
Luego una guía práctica de:
- “qué hago según el escenario”

Es la capa de entrada operativa.

### 3. workflow map
Después el mapa estructural:
- qué skill usar
- en qué orden
- cuáles son obligatorias/opcionales

### 4. schema mínimo
Luego la validación base:
- estructura mínima del brief
- campos esenciales

### 5. templates
Después los artefactos base:
- brief full
- brief lite
- spec
- tasks
- review
- retrospective
- migration

### 6. skills
Luego las capacidades que operan sobre esos artefactos:
- brief-to-prd
- prd-to-spec
- spec-to-tasks
- change-review
- etc.

### 7. agents
Después los agentes simples que componen skills según un rol:
- reviewer
- migration guardian
- endpoint designer
- inception architect

### 8. context
Luego el contexto persistente/local:
- system layers
- decisions
- pitfalls
- working memory

### 9. memory fallback
Esto realmente es una subcapa de context, pero si lo separas en flujo:
- entra aquí cuando no hay Engram
- sostiene continuidad operativa

### 10. migration planning
Al final, como capacidad especializada para sistemas vivos:
- cuando ya hay operación
- cuando cambias reglas
- cuando haces transición segura

1. **governance**
2. **context**
3. **schema mínimo**
4. **templates**
5. **skills**
6. **agents**
7. **quick-start**
8. **workflow map**
9. **memory fallback**
10. **migration planning**

Porque:
- quick-start y workflow map son más bien **capas de navegación**
- context/schema/templates/skills/agents son más bien **capas del sistema**
