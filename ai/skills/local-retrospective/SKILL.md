# Local Retrospective

## Goal

Cerrar ciclos de trabajo con aprendizaje práctico y accionable.

## When to use

- al cerrar una feature o cambio relevante;
- después de una falla o rollback;
- después de varias iteraciones del mismo problema;
- al final de una sesión de trabajo importante.

## Workflow

1. Resumir el objetivo.
2. Capturar:
   - qué salió bien
   - qué salió mal
   - qué fue confuso
   - qué se repitió
3. Identificar 1-3 mejoras concretas.
4. Decidir dónde viven:
   - improvement-loop
   - decisions.md
   - pitfalls.md
   - una skill nueva o ajustada

## Output format

### 1. Goal
- qué intentábamos lograr

### 2. Worked Well
- prácticas útiles

### 3. Problems
- fallas, fricción o ambigüedades

### 4. Repeated Patterns
- qué se repitió

### 5. Action Items
- ajuste concreto
- dueño implícito o destino

## Rules

- no convertir la retrospectiva en ensayo largo;
- no listar veinte acciones sin prioridad;
- registrar solo mejoras que realmente cambian el flujo.
